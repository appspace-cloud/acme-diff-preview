Adds a merge-blocking guard for a config pattern that silently breaks image names (COPR-31637).

- **New guard:** a PR that sets `appspace.microservices.definitions` to a null/empty map in any value file is now blocked with a red build status + an explanatory comment. On merge, an empty `definitions` wipes every per-service `image.name` override the chart ships, so services fall back to derived `appspace-<key>` names that have no images — cluster-wide `ImagePullBackOff` (exactly the `pv-qa11-a` incident).
- A **missing** `definitions` key stays allowed (the chart's map is kept); only present-but-empty is blocked. Transient fetch errors and unparseable YAML never block.
- Documented the convention in the README ("Merge-blocking guards") and in `docs/microservices-definitions-guard.md`.

Tests: 14 new (red-green confirmed), full suite green, coverage 100%.
